换领域 ≠ 换框架：领域 Agent 配方

pi 的三层架构在这里兑现价值：大脑（AgentHarness + 循环）一行不改，动的只是产品层的四样东西——系统提示词、工具集、上下文策略、守卫。所以「搭一个 X 领域的 agent」不是新工程，是填一张配方卡。

领域 Agent = 循环(不变) × 系统提示词 × 工具集 × 上下文策略 × 守卫 × 评测
应用篇 · 第 2 站

多 Agent 协作：五种编排模式（先泼冷水）

编排不在 pi/tau 的循环里——这是刻意的：编排是循环之上的一层。你可以用「子代理即工具」在任何 harness 上把它长出来。但先看成本，再看模式。

❄️ 上多 agent 之前，先读这三行

· Anthropic 实测（《How we built our multi-agent research system》）：单 agent 任务消耗约 4× 于普通对话的 token，多 agent 系统约 15×——收益必须配得上这张账单。

· Cognition《Don't Build Multi-Agents》的警告：并行子 agent 看不见彼此的中间决策，各自的产出携带互相冲突的隐式假设——先把单线程 + 上下文工程做到头。

· pi/tau 的立场（本教程一以贯之）：先「单 agent + 更好的工具 + 更好的上下文」，仍不够，再编排。

✅ 判据（至少中两条再上）：① 子任务只读、彼此独立、可并行② 主上下文确实会被撑爆③ 子任务需要不同的工具集/提示词

编排层选型：先自写，需求硬了再上框架

  

    
① 自写并发原语（默认）
≤ 一屏代码的场景：Python 的 asyncio.TaskGroup、Rust 的 JoinSet + Semaphore。rust-ai-agent 的 bin/gaia.rs 就是现成示范——20 行搞定 fan-out + 限流 + 汇总。

    
② LangGraph（图状态机）
当你真的需要：图里带环的回退、按节点断点续跑、人工审批卡点作为一等公民。代价：控制反转——框架拥有执行。对照主文档第 11 章的 7 问决策清单再决定。

    
③ Temporal / 工作流引擎
当编排要跨天跨机器存活（重启不丢、重试有审计、SLA）。这时「外层 Temporal 编排 + 内层薄 harness」的混合策略最稳——循环仍然是你的。

做

别

做

● 完整实现◐ 部分 / 雏形○ 留白（刻意不做）— 没有

  

  

    
pi 是唯一的全覆盖——除了评测（X3）和编排（L5）。前者它靠 Terminal-Bench 等外部基准；后者刚从"哲学留白"变成"实验孵化"：orchestrator 作为独立第五包出现在 harness 之外。

    
rust-ai-agent 反向互补：核心六层基本空白（ep05 刚长出单轮工具调用），却有 pi/tau 都没有的评测脊椎（X3 的 evaluator.rs）+ 重试（backon）+ 并发限流。

    
L5 的留白正在被填：编排天然长在 harness 之上——「子代理即工具」只需注册一个工具。pi 用实验性 orchestrator 包开始官方试探，而它长的位置（独立包、不动七层）恰好证明「编排属于上层」（详见第 4 站演进案例）。

构架篇 · 第 4 站

  
活案例：72 小时上游演进，全部落进蓝图

  
蓝图切得准不准，最硬的检验是：真实世界的改动能不能一格格放进去。2026-07-16 → 07-19 三天里，pi 发了三个版本（0.80.8/9/10）、tau 发了两个（0.2.0/0.2.1）、共 60+ 个提交——下表把主要改动逐条映射到第 1 站的 7+4 蓝图。先看两个「预言兑现」。

  

    
🏆 预言兑现 ①：事件流契约的价值，被上游投票了。
tau 0.2.0 的核心提交叫 adopt Pi-compatible event and extension protocol——一个独立实现主动采纳另一个实现的事件协议，还把 canonical event streams 写成了文档。本教程 L1 一直讲「事件流是唯一契约」：契约稳定，实现可以各自演化、甚至互操作。这就是证据。

    
🏆 预言兑现 ②：L5 的留白，官方开始填了。
覆盖矩阵曾把 pi 的编排层标为 ○ 刻意留白。本次复核发现 pi 的第五个包 pi-orchestrator（2026-06 起孵化，README 自标 Experimental：IPC server / supervisor / 多实例存储）。注意它长的位置——harness 之上的独立包。「编排属于上层」的分层判断被官方路线确认。
