✗ 它不是"用 Rust 复刻的 tau"

tau 是 pi 有文档记载的 Python 复刻；rust-ai-agent 和 pi/tau 没有复刻关系，也没有 agent 循环、没有工具调用、没有会话。它只是碰巧也是教学项目。

✓ 它是"增强 LLM + 结构化输出 + 评测"教程

每次 LLM 交互都是单次调用。核心是：4 种调用模式 + 两种结构化输出流派 + 一个跑 GAIA 基准的评测器。站在 Anthropic 光谱的 workflow 端，是 pi/tau（agent 端）的互补前传。

核心知识点 1

  
结构化输出的两种流派

  
这是 rust-ai-agent 教得最扎实、也最容易被忽视的一课：让模型返回结构化数据有两条路，代码就差一行 ResponseFormat，但适用场景完全不同。点标签切换看真实代码。

  

    

    

      

      

        

      

    

  

  

    
流派ResponseFormatschema 从哪来何时用代价

    
      
schema 强约束JsonSchema{strict:true}schemars 从 Rust 类型 derive端点支持 strict JSON schema（OpenAI、部分 OpenRouter 模型）不是所有模型/网关都支持

      
提示词强制JsonObject + schema 写进系统提示词同样 schemars derive，但序列化成文本塞进 prompt模型只支持"给我 JSON"不支持 schema（如早期 DeepSeek，_ds 由此得名）模型可能不严格遵守，需 serde 兜底 + 重试

    
  

  
这正好是主教程第 10 章「逃生舱」思想的 Rust 实现：能力不齐时降级到提示词强制。三个项目凑齐了工具/输出 schema 的三种流派——tau 手写 dict、pi 用 TypeBox、rust-ai-agent 用 schemars derive（类型安全最强）。

动手 · 跟着学

  
怎么真正跑起来 + 升级成"真 agent"

  

    

      
① 环境与运行

      
    
        
  • 克隆并按集数 checkout：git checkout ep04
    • 
        
  • 它用 OpenRouter（模型名 openai/gpt-4.1-mini、anthropic/claude-haiku-4.5 是 OpenRouter slug）。.env 里设 OPENAI_API_KEY = OpenRouter key、OPENAI_BASE_URL = OpenRouter 端点——async-openai 自动读这两个环境变量。
    • 
        
  • 跑 GAIA 评测还需 HF_TOKEN（从 HuggingFace 拉数据集）。
    • 
        
  • 两个入口：cargo run（main.rs：ActionPlan 结构化输出 demo）；cargo run --bin gaia（GAIA 评测实验）。
    • 
      

    

    

      
② 集数 → 文件对照

      

        
ep01–02llm/complete.rs·stream.rs —— 文本 / 流式基础调用

        
ep03llm/structured.rs·structured_ds.rs —— 结构化输出两流派

        
ep04gaia/*·bin/gaia.rs —— GAIA 数据集评测

      

      
（仓库当前只有 ep04 tag、6 个 commit——早期项目，后续集数可能长出工具循环。）

    

  

  

    双向取长补短。想把它升级成 pi/tau 那样的循环式 agent？缺的正是主教程第 9 章 M3–M8 教的：把 solve_problem() 的单次调用包进 while，读 tool_calls（async-openai 原生支持）→ 执行 → 结果回填 → 重复；给 GAIA 配 web-search / read-file / python-exec 工具（而非 coding 的 edit/bash）。反过来，它的 evaluator.rs 恰好是 pi/tau 都缺的评测脊椎——做你的 mini（第 9 章）的 M10 时把它借过来。
