诚实边界

书的 coding-agent 不是每一关都有对应

它是扁平单目录实现，这本身就是一课

书的 chapter5/coding-agent 追求「一个文件夹跑起来」，所以没有 pi/tau 那种严格分层：没有 provider 中立事件层（M2）、没有独立类型层（M1）、没有 append-only 会话树（M7）。这几关它的「参考」列会标成灰色空缺。

这不是缺点，是取舍对照：把书的扁平 agent.py（513 行什么都塞在一起）和 tau 的分层（loop.py 318 / harness.py 244 / session/ 各司其职）并排看，你会亲眼看到「分层到底买来了什么」——这正是 M0 依赖方向守卫想教你的东西。

反过来，书的 coding-agent 在工具丰富度上更像 Claude Code：19 个工具含 task_tool.py（子代理即工具，M11 的现成样板）、todo_write_tool.py、exit_plan_mode_tool.py——这些是 mini/tau 的精简版里没有的。取长补短。

现在就开工

三条命令，跑起 M0/M1，进入 M2

零等待起步（M0/M1 已完成、开箱全绿）

# 1. 进工程、装依赖（uv 会读 pyproject.toml + uv.lock）
cd agent-study/mini && uv sync

# 2. 跑一遍验收：M0 依赖方向守卫 + M1 类型，应全绿
./check.sh                          # ✓ ruff + mypy strict + pytest

# 3. 进入 M2 练习：打开 provider 适配器的 TODO 骨架开写
#    要点清单在文件头，卡住看 tau_ai/ 或 solutions/
$EDITOR src/mini_ai/openai_compatible.py

# 想先看 M3 循环练习怎么验收（默认跳过，动手时启用）：
MINI_MILESTONE=3 uv run pytest tests/test_loop_spec.py -v
